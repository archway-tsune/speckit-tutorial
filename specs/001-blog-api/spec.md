# 機能仕様書: ブログ記事管理API

**フィーチャーブランチ**: `001-blog-api`
**作成日**: 2026-01-28
**ステータス**: ドラフト
**入力**: ユーザー説明: "ブログ記事管理APIの仕様を作成してください"

## ユーザーシナリオ＆テスト *(必須)*

### ユーザーストーリー 1 - ユーザー登録とログイン (優先度: P1)

ブログサービスを利用したい新規ユーザーが、アカウントを登録してログインし、認証済みのセッションを取得する。

**この優先度の理由**: 認証システムは他のすべての保護された機能の基盤となるため、最初に実装する必要がある。

**独立したテスト**: 登録フォームに入力し、確認メールなしでログインできることを確認することで、完全にテスト可能。価値として、ユーザーは自分のアカウントを持ち、コンテンツを管理できるようになる。

**受け入れシナリオ**:

1. **Given** 未登録のユーザーがいる、**When** 有効なメールアドレスとパスワードで登録する、**Then** アカウントが作成され、ログイン可能になる
2. **Given** 登録済みユーザーがいる、**When** 正しい認証情報でログインする、**Then** JWTアクセストークンとリフレッシュトークンが発行される
3. **Given** 認証済みユーザーがいる、**When** アクセストークンが期限切れになる、**Then** リフレッシュトークンで新しいアクセストークンを取得できる
4. **Given** 認証済みユーザーがいる、**When** ログアウトする、**Then** トークンが無効化される

---

### ユーザーストーリー 2 - 記事の作成と公開 (優先度: P1)

ブログ著者が新しい記事を作成し、下書きとして保存するか、すぐに公開する。

**この優先度の理由**: 記事作成はブログプラットフォームの核心機能であり、コンテンツなしではサービスの価値がない。

**独立したテスト**: 認証後、新しい記事を作成し、それがシステムに保存されることを確認することでテスト可能。

**受け入れシナリオ**:

1. **Given** 認証済みユーザーがいる、**When** タイトルと内容を入力して記事を作成する、**Then** 記事がデフォルトで下書きステータスで保存され、著者名はログインユーザー名から自動設定される
2. **Given** 下書き記事がある、**When** ステータスを「published」に更新する、**Then** 記事が公開され、一覧に表示される
3. **Given** 認証済みユーザーがいる、**When** タイトルなしで記事を作成しようとする、**Then** バリデーションエラーが返される

---

### ユーザーストーリー 3 - 記事の一覧表示と閲覧 (優先度: P2)

読者がブログの記事一覧を閲覧し、興味のある記事の詳細を読む。

**この優先度の理由**: 公開された記事を閲覧できなければ、ブログとしての価値を提供できない。

**独立したテスト**: 記事一覧エンドポイントにアクセスし、公開済み記事が表示されることを確認することでテスト可能。

**受け入れシナリオ**:

1. **Given** 公開済み記事が複数ある、**When** 記事一覧を取得する、**Then** ページネーション付きで記事が返される
2. **Given** 公開済み記事がある、**When** 記事IDを指定して詳細を取得する、**Then** 記事の全情報が返される
3. **Given** 下書き記事がある、**When** 未認証で記事一覧を取得する、**Then** 下書き記事は一覧に含まれない

---

### ユーザーストーリー 4 - 記事の更新と削除 (優先度: P2)

ブログ著者が既存の記事を編集したり、不要な記事を削除する。

**この優先度の理由**: コンテンツのライフサイクル管理はブログ運営に必要な機能である。

**独立したテスト**: 既存記事のタイトルや内容を更新し、変更が反映されることを確認することでテスト可能。

**受け入れシナリオ**:

1. **Given** 認証済みユーザーと自分が作成した記事がある、**When** 記事のタイトルを更新する、**Then** 変更が保存され、updatedAtが更新される
2. **Given** 認証済みユーザーと自分が作成した記事がある、**When** 記事を削除する、**Then** 記事がシステムから削除される
3. **Given** 未認証ユーザーがいる、**When** 記事を更新しようとする、**Then** 認証エラーが返される
4. **Given** 認証済みユーザーがいる、**When** 他のユーザーの記事を更新しようとする、**Then** 権限エラーが返される

---

### ユーザーストーリー 5 - 記事の検索とフィルタリング (優先度: P3)

読者が特定の条件で記事を絞り込んで検索する。

**この優先度の理由**: 記事数が増えた際のユーザビリティ向上に貢献するが、基本機能ではない。

**独立したテスト**: ステータスフィルターやソートパラメータを指定して、期待通りの結果が返ることを確認することでテスト可能。

**受け入れシナリオ**:

1. **Given** 公開済みと下書きの記事がある、**When** status=publishedでフィルタリングする、**Then** 公開済み記事のみが返される
2. **Given** 複数の記事がある、**When** 作成日で降順ソートする、**Then** 新しい順に記事が並ぶ

---

### エッジケース

- タイトルが200文字を超える場合、バリデーションエラーが返される
- ページネーションで範囲外のページを指定した場合、空の結果が返される
- limitが100を超える場合、100に制限される
- 存在しない記事IDを指定した場合、404エラーが返される
- JWTトークンが改ざんされている場合、認証エラーが返される
- レート制限を超えた場合、429エラーが返される
- リフレッシュトークンが期限切れの場合、再ログインが必要である
- 他のユーザーの記事を更新・削除しようとした場合、403エラーが返される
- 他のユーザーの下書き記事にアクセスしようとした場合、404エラーが返される（存在を隠す）

## 要件 *(必須)*

### 機能要件

#### 認証関連

- **FR-001**: システムはユーザーがメールアドレスとパスワードで新規登録できなければならない
- **FR-002**: システムはパスワードをbcryptでハッシュ化して保存しなければならない
- **FR-003**: システムは登録済みユーザーのログイン時にJWTアクセストークンを発行しなければならない
- **FR-004**: アクセストークンは発行から1時間有効でなければならない
- **FR-005**: システムはリフレッシュトークンも同時に発行しなければならない
- **FR-006**: リフレッシュトークンは発行から7日間有効でなければならない
- **FR-007**: システムはリフレッシュトークンを使用して新しいアクセストークンを発行できなければならない
- **FR-008**: システムはログアウト時にトークンを無効化しなければならない
- **FR-009**: 認証関連エンドポイントはレート制限（1分あたり5リクエスト）を適用しなければならない

#### 記事管理関連

- **FR-010**: システムは認証済みユーザーが新しい記事を作成できなければならない
- **FR-011**: 記事にはid（UUID）、title、content、author、status、authorId、createdAt、updatedAtフィールドが含まれなければならない。authorIdは記事作成時にログインユーザーのIDが自動設定される
- **FR-012**: タイトルは必須で、1文字以上200文字以下でなければならない
- **FR-013**: 内容（content）は必須でなければならない
- **FR-014**: 著者（author）は記事作成時にログインユーザーの名前から自動設定されなければならない
- **FR-015**: ステータスは「draft」または「published」のいずれかでなければならない
- **FR-016**: 新規作成時のデフォルトステータスは「draft」でなければならない
- **FR-017**: システムは認証済みユーザーが自分が作成した記事のみを更新できなければならない
- **FR-018**: システムは認証済みユーザーが自分が作成した記事のみを削除できなければならない
- **FR-019**: システムは認証なしで公開済み記事の一覧を取得できなければならない
- **FR-020**: システムは認証なしで公開済み記事の詳細を取得できなければならない
- **FR-021**: 下書き記事は作成者本人のみがアクセスできなければならない

#### クエリ機能関連

- **FR-023**: 記事一覧はページネーション（page、limit）をサポートしなければならない
- **FR-024**: ページネーションのデフォルト値はpage=1、limit=10でなければならない
- **FR-025**: limitパラメータの上限は100でなければならない
- **FR-026**: 記事一覧はステータスによるフィルタリングをサポートしなければならない
- **FR-027**: 記事一覧はソート（sort）をサポートしなければならない

#### エンドポイント認証要件

- **FR-028**: 以下のエンドポイントは認証不要でアクセスできなければならない
  - `GET /api/v1/posts` - 公開済み記事一覧の取得
  - `GET /api/v1/posts/:id` - 公開済み記事詳細の取得
  - `POST /api/v1/auth/login` - ログイン
  - `POST /api/v1/auth/register` - 新規登録
- **FR-029**: 以下のエンドポイントはJWT認証が必須でなければならない
  - `POST /api/v1/posts` - 記事作成
  - `PUT /api/v1/posts/:id` - 記事更新
  - `DELETE /api/v1/posts/:id` - 記事削除
  - `POST /api/v1/auth/refresh` - トークン更新
  - `POST /api/v1/auth/logout` - ログアウト

#### エラーレスポンス

- **FR-030**: すべてのエラーレスポンスは統一フォーマットで返されなければならない
- **FR-031**: エラーレスポンスは以下の形式でなければならない
  ```
  {
    "error": {
      "code": "エラーコード（例: VALIDATION_ERROR, UNAUTHORIZED）",
      "message": "ユーザー向けエラーメッセージ",
      "details": [オプション] 詳細情報の配列
    }
  }
  ```
- **FR-032**: 主要なエラーコードは以下を含まなければならない
  - `VALIDATION_ERROR` - 入力バリデーションエラー（422）
  - `UNAUTHORIZED` - 認証エラー（401）
  - `FORBIDDEN` - アクセス権限エラー（403）
  - `NOT_FOUND` - リソース未発見（404）
  - `RATE_LIMIT_EXCEEDED` - レート制限超過（429）
  - `INTERNAL_ERROR` - サーバー内部エラー（500）

### 主要エンティティ

- **ユーザー（User）**: ブログシステムの登録ユーザー。認証情報（メールアドレス、パスワードハッシュ、ユーザー名）を持ち、自分の記事の作成・編集・削除が可能
- **記事（Post）**: ブログの投稿コンテンツ。タイトル、本文、著者名（author）、所有者ID（authorId）、公開ステータス、タイムスタンプを持つ。authorIdにより作成者との紐付けが管理される
- **認証トークン**: ユーザーセッションを管理するJWTトークン。アクセストークン（1時間有効）とリフレッシュトークン（7日間有効）の2種類がある

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: ユーザーは2分以内にアカウント登録を完了できる
- **SC-002**: ログイン処理は3秒以内に完了する
- **SC-003**: 記事一覧の取得は1秒以内に応答する（100件以下の場合）
- **SC-004**: 記事の作成・更新操作は3秒以内に完了する
- **SC-005**: システムは100人の同時ユーザーをパフォーマンス低下なく処理できる
- **SC-006**: 認証エラーや入力バリデーションエラーの際、ユーザーに明確なエラーメッセージが表示される
- **SC-007**: 不正な認証試行は適切にブロックされ、ログに記録される
- **SC-008**: トークンの有効期限切れ時、ユーザーはシームレスにトークンを更新できる

## 前提条件と仮定

### 前提条件

- ユーザーはメールアドレスでの登録のみをサポート（SNS連携は対象外）
- シングルテナント構成（マルチテナントは対象外）
- 記事へのコメント機能は対象外
- メディアファイルのアップロード機能は対象外
- 記事のカテゴリやタグ機能は対象外

### 仮定

- ページネーションのデフォルト値: page=1, limit=10、limitの上限は100
- ソートのデフォルト: createdAtの降順（新しい順）
- sortパラメータで指定可能なフィールド: createdAt, updatedAt, title
- ソート順序の指定: フィールド名の前に「-」をつけると降順（例: -createdAt）
- 削除は物理削除（論理削除ではない）
- 1ユーザーが複数の記事を作成可能
- 記事の著者（author）はログインユーザーの名前から自動設定される
- 記事の所有者（authorId）はログインユーザーのIDが自動設定される
- 記事の更新・削除は作成者本人のみ可能（他のユーザーの記事は操作不可）

## スコープ外

- ソーシャルログイン（OAuth）
- 二要素認証
- パスワードリセット機能
- メール確認フロー
- 記事へのコメント機能
- 記事のカテゴリ・タグ機能
- 画像・メディアアップロード
- 全文検索機能
- 多言語対応
- 管理者ダッシュボード
